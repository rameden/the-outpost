The accountant's import rejected this month's invoice export. Every row for Acme, Inc. has one column too many, so the due date lands in the "issued on" column and the total in "due on".

## What happens

A customer name with a comma in it is written to the CSV as it is, so a spreadsheet reads it as two fields. A name with double quotes in it (we have a customer called Dana "DJ" Okafor Design) also comes out wrong when it is opened.

## How to reproduce

1. Export invoices that include one for the customer Acme, Inc.
2. Open the file in a spreadsheet, or count the commas on that row.

The row has six fields under a five-column header.

## What should happen

The file follows the usual CSV rules (RFC 4180): a field that contains a comma, a double quote or a line break is wrapped in double quotes, and a double quote inside it is written twice. Acme, Inc. becomes "Acme, Inc." and stays in one column. Fields that need no quoting are written as they are today, so existing imports keep working.

## Acceptance criteria

- Every row has exactly five fields when read by a CSV parser, whatever the customer is called
- A field with a comma, a double quote or a line break is quoted, with inner quotes doubled
- Rows with nothing to quote are byte-for-byte what they are today
- The tests for this ticket pass and are no longer marked as open
