Outpost

Your outpost. Your crew. Your call.

Outpost is where a small crew of agents takes on your work the way you'd want it done, in outposts of your own: one for work, one for home, each with the name you give it. The Quartermaster turns your request into a plan, waits for your OK, then sends a Scout, a Scribe and an Artificer out on quests, several at once, with a Warden to review what changed and a Test Pilot for the hardest problems. Each one keeps its own memory, its own workspace and its own limits. It's for people who already use Claude and want more of the work done while they get on with theirs.

How an expedition runs

You approve the plan. The crew does the legwork.

1

Ask

Type a request in mission control or the terminal. If it could mean two things, the Quartermaster asks you one short question first.

2

Approve the plan

The plan fills in step by step. Approve it and start, approve it now and start it later from its card or from Today, or ask for changes. A budget, if you have set one, covers the whole expedition.

3

Quests set out

Up to four run at once. Each crew member starts clean from a written brief, so nobody drags the whole conversation along.

4

Reports come home

The Quartermaster reviews each report, sends a failed check back to be fixed, can have the Warden look over the change, and hands you one next step.

Outpost and Claude Code

Claude Code is one agent you steer. Outpost is a crew you brief.

With Claude Code on its own, you hold one conversation and guide it turn by turn. Outpost puts a planner in front of that and a reviewer behind it. On a subscription, Claude Code is still what runs each crew member, on the same account and the same usage limits.

You approve once

The Quartermaster turns your request into a plan of quests. You approve it, ask for changes, or hold it for later. After that you don't have to watch.

Several at once

Up to four quests run side by side. Each crew member starts from a written brief, with its own memory, workspace and limits, so no single conversation has to carry everything.

Checked before you see it

The Quartermaster reads every report and sends a failed check back to be fixed. The Warden can review what changed. You get one summary and one next step.

It also keeps going while you're away: jobs on a schedule, and approvals from your phone. If one conversation with Claude Code is doing the job, you don't need Outpost. It earns its place when the work splits into parts.

Outpost rules

Clear limits, kept by the outpost's own code.

An agent can't talk its way past these. The camp's own source is read-only to the crew, so nothing it reads can loosen them.

Secrets stay put

File tools never read .env, private keys or credentials, at any depth, in a linked folder or through a symlink.

Commands travel light

Your API keys and tokens are left out of every command and connector the crew starts, unless you name one to pass on.

The key isn't in the link

The link the camp prints signs one browser in, once. The camp's key never sits in an address, your history or a bookmark.

Shell asks first

Commands need your OK, stop after two minutes, and stop when you press Stop. A sandbox is there if you want it, on macOS or Linux. God mode, for the camp or one project, runs every command without asking, but "Never run" rules still stop one, and a scheduled job gets the sandbox instead.

Deleting asks first

Uploads, worktrees and old records are cleared only when you ask, a step at a time, each showing what will go.

Read-only git

Everyone can run status, diff, log and blame. Nobody pushes on their own.

No trampling

Parallel quests can't overwrite each other. A file changed by another quest has to be read again first.

Pages are information

Web pages, files and connector results are never treated as instructions, and suspected prompt injection is flagged.

Budgets hold

Spending is tallied after every reply, across all quests, and the run stops when the budget is reached.

Costs

What it costs, and how it keeps spending in check.

Outpost itself is free and open source. You pay for the model calls, the same way you would using Claude yourself.

On a subscription

Runs count against your Pro or Max plan's usage limits. The costs you see in the outpost are estimates at API prices, from what Claude Code reports a run would have cost. A chip in the header says when a run is drawing on extra-usage credit.

On an API key

Every call is billed to your key, apart from any subscription. A key saved in Settings → Models is used before ANTHROPIC_API_KEY in .env.

Budgets

Set a spending cap per expedition under Settings → Limits & budget, or with /budget in the terminal. It covers the Quartermaster and every quest it sends, and the run stops when it's reached.

Which model

Most of the crew starts on Sonnet, and a Test Pilot on Opus. Pick Auto and it chooses per task: Economy for the cheapest model that can do it, Quality for the one most likely to finish, Balanced (the default) in between. The outpost's own small jobs, like naming a conversation, use the cheapest small model that's up to it.

The name

Outpost is the app. Each outpost takes the name you give it.

The app is Outpost, and each camp it runs is an outpost: a place you go, where the crew stationed there does the work. It's the crew you'd be if there were more of you. They plan before they act, show you the plan, and nothing leaves the outpost without your click. The orb is the outpost's own light. It meets you at the door when you sign in to mission control, and it has two moods: at rest and at work.

The crew

Six specialists who know their trade, and stay in it.

Each crew member has a fixed identity. They grow their memory, but they can't rewrite who they are. Ask one for work outside its role and it declines in one line, naming the right teammate.

The kit

Everything in the kit.

Mission control

A local dashboard for the whole outpost

Launch an outpost from the star chart (npm start) and it opens at localhost. Out of the box only this machine can reach it; the Outposts tab has the ways in from elsewhere. Conversations filed under projects, a live feed, approvals as buttons, a file pane, a terminal along the bottom, and a layout you arrange yourself.

  • Steer or stop a run mid-quest, and resume it later
  • While a run works, Send becomes Stop, and Enter queues your next message behind it
  • Tool calls fold into one line per stretch ("Read 5 files, ran 2 commands"), and a Condensed/Detailed switch brings back every line
  • Attach a file, a folder, or a .zip that arrives as the folder it holds, up to 5,000 files
  • Mention @scribe anywhere in a plain chat and the Scribe takes that turn
  • Worktrees and linked folders for work you want kept apart
  • Changes you can review and undo
  • Sign in once per browser. A tab left open carries on when the camp restarts
  • Release notes, in the sidebar, sum up what's changed in Outpost itself: every 48 hours, from the pull requests merged into its repository, front end and back end apart
Voice

Read aloud

Connect an ElevenLabs key under Settings → Voice and Outpost reads to you in the voice you choose: an answer, a job's report, an inbox item, a ticket's debrief, or text you select. One player in the top bar pauses, skips and changes speed, and stays as you move around. Each piece is kept, so hearing it again costs nothing.

Skills

How-tos the crew picks up

After a good expedition the Quartermaster can propose a skill: the steps, the format, the pitfall that cost a retry. It goes live only when you approve it. Import a skill pack, or set one to apply to everything a crew member does.

Auto, the router

A router picks the model for each task

Set a crew member, a project or one conversation to Auto: Economy, Balanced or Quality. Right before each dispatch the router sizes up the task (how hard it is, how much is at stake, how big the request is), rules out every model that can't carry it, and picks the cheapest that should finish, or the likeliest to.

  • It keeps a model through routine work, and moves on when one is failing, rate limited or too small for the conversation
  • An outage is waited out, not given up on, and a model you pick yourself stays pinned
  • It learns from how each run actually went, within a limit, so one good or bad day doesn't decide a model's fate
  • Every run says which model it used and why. Settings → Models shows how Auto's runs have gone, with a switch for each model Auto may pick (you can still pick one it may not)
Projects & Jira

From a note to a pull request

Jot a note and the Scout can write it up as a ticket with acceptance criteria, or ask for ideas and get up to five from the project's record. Start from a Jira ticket, step by step. Pull requests go out with a real description, from your own button, and review comments come back for you to read.

Tickets & debriefs

Tickets of its own, and a look back when one's done

No Jira? Outpost keeps its own tickets, keyed MAE-1, MAE-2 and on, on a Tickets page. Turn a note or a plan into tickets with one button, or let the Quartermaster make them.

  • A ticket moves to In progress when work starts, and to Done when its pull request merges
  • When a ticket is done, one of its own or a Jira one, the smallest model reads how the crew did on it: the plan, each quest, what reviews and checks caught, what you had to ask for twice
  • It proposes lessons, and nothing is kept until you approve it. It has a switch of its own, with the other things the outpost does unasked
While you're away

It keeps an eye on the work

Each part has its own switch, and nothing it starts goes ahead without your OK.

  • Scheduled jobs report to an inbox and a macOS notification, and stay quiet when there's nothing new
  • A morning brief each weekday on the Today page: what's waiting on you, what's in motion, what's next
  • Your pull requests are followed, and new review comments or a failed check come back as a plan to approve
  • A weekly retro proposes what's worth remembering from the week's corrections, and drafts a how-to for work you keep asking for. Nothing is kept until you approve it
  • A night shift, off until you switch it on, uses the quiet hours to draft shorter versions of memories that are getting full, list old lines worth a look and note what housekeeping could clear. It only drafts and reports: the morning's Today page shows what it left, and nothing changes until you approve it
  • A scoreboard counts how much of what you typed was deciding, and how much was operating the pipeline, and a weekly chronicle shows whether the camp is paying off
  • Is it paying off?, on each project's page, counts the last 30 days: what reviews, second opinions and failed checks turned up, what they used, and how the project's pull requests went, so you can switch off what isn't earning its keep
Housekeeping

It tidies up when you say

Ask the Quartermaster to clean up the camp. It lists what could go (unused uploads, finished worktrees, leftovers from a crash), then asks before each step and shows exactly what will be removed.

Built for every day

Leave it running

The camp's own files are written whole or not at all, so a crash can't leave one half-written. A reply cut off by a dropped connection is asked for again. Stop the camp and its running work stops with it, with a Resume button waiting on each run.

  • A run picked up again, even on another model, never repeats a command, pull request or review
  • A settings file with a typo is set aside, not silently replaced
  • Checks you list run after every change, and a failure goes back to be fixed
  • Budgets hold even on a model too new to have a listed price
Outposts

One app, as many outposts as you need

Each outpost is a camp of its own: one for work and one for home, say, that know nothing of each other. The first one lives in the folder you cloned, in its camp/. The others live in ~/Outposts/<name>/, and each runs as its own server on its own port.

  • Each has its own crew, memory, settings, keys, jobs, skills and .env
  • A new outpost starts empty: connect its models and accounts from its own Settings
  • The crew's built-in skills are brought up to date each time an outpost starts, while the skills an outpost learns stay in that outpost
  • The header reads Outpost with the outpost's name under it, and so do the tab title, notifications and Jira notes, so you always know which one you're in
  • Rename one under Settings → General → Outpost name: it shows at once, while its folder stays where it is

Orbit is mission control at full screen. The Quartermaster is the sun and each crew member a planet that lights up while it works. Watch

Click a planet and the camera flies to it and stays there. Its panel shows each quest, how long it has been out, its last few steps, and a reply as it's written. The sun's panel shows the running expeditions and where each plan stands.

Act

Answer a question, steer a quest, stop one or send new work from the panel, without leaving the view. Stopping a whole expedition asks you once first.

Replay

Scrub back through the day on a timeline. Demo plays a pretend camp, so you can see it busy without sending anyone anywhere. HD draws the system in three dimensions, as worlds you can make your own.

From the plan

Trail map

The plan's card shows its steps as a list or as a trail (List and Trail), and Full screen on the card, or /trail, opens the trail map over the whole page. Each step is a waypoint with who was sent on it and how it stands, and a line runs from a step to each step that has to wait for it. It fills in as the crew works, and replays the day the same way. Whole map (or M) puts every plan on one map, drawn one of two ways, and Tree and Rings (or R) swap between them. As rings, the way Orbit draws the crew: each plan is a ring round one centre, the first asked innermost, so the map grows outward as the day goes on. Its steps are waypoints on the ring, with whoever was sent on one beside it, and the plans of one conversation start on the same bearing and are joined, ring to ring. As a tree: one trunk for the day, standing on the foot of the window and growing upward, the first plan at the bottom and the newest at the tip, each plan a bough growing off it. Either way it holds the whole last day (the same day a replay plays, so a replay ends on the map you started from), it's drawn as small as it takes to fit, and fitted again as plans join, and the way you chose is remembered. A plan that joins while you watch, live or in a replay, is drawn in (a ring opens out, a bough grows) while the rest move over for it, and one that goes when you wind a replay back fades where it stood.

FAQ

Questions people ask first.

Is my data sent anywhere?

Only to the model you run it on: Anthropic, through Claude Code or your API key, or another provider if you connect one. There's no telemetry or analytics. Your outpost is a folder on your machine, and mission control opens at localhost, which only this machine can reach unless you open it to your home network or put your own relay or Tailscale in front of it. If you turn on phone approvals, the approval's text goes to your ntfy server.

Does it use my Claude Code settings?

No. It signs in with your Claude Code account, but your settings, hooks, CLAUDE.md, skills and MCP servers aren't loaded for the crew, and runs aren't saved as Claude Code sessions. Claude Code's own file and shell tools are off: the crew uses the outpost's tools, so its approvals apply.

Does it run on Windows or Linux?

It's built on macOS first. Windows works, in Git Bash or PowerShell, but without a sandbox (use WSL 2 for one). Linux isn't tested yet: the sandbox needs bubblewrap, and the terminal pane needs node-pty built (npm rebuild node-pty). Everything but the terminal pane works without it.

How is this different from using Claude Code on its own?

Claude Code is one agent you talk to. Outpost puts a planner in front: you approve a plan, then specialists work on it several at once, each with its own memory, workspace and limits, and a reviewer checks what changed. It can also run jobs on a schedule while you're away. On a subscription, Claude Code is what runs each of them.

What's an outpost, and who is Mae?

Outpost is the app. An outpost is one running copy of it: its own folder, crew, memory and server, so work and home can stay apart. Your first outpost is called Mae (short for My Alter Ego) until you rename it under Settings → General → Outpost name.
