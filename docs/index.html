The crew

Five specialists who know their trade, and stay in it.

Each crew member has a fixed identity. They grow their memory, but they can't rewrite who they are. Ask one for work outside its role and it declines in one line, naming the right teammate.

🧭

Quartermaster

Plans, briefs the crew, reviews reports, schedules recurring jobs.

Doesn't
Specialist work. It dispatches that instead.

🏹

Scout

Research: web search and fetch, local files, findings with sources.

Doesn't
Polished writing or code.

🪶

Scribe

Writing and editing: docs, posts, emails, READMEs.

Doesn't
Code or new research.

🔨

Artificer

Code: reads, edits, runs and tests, with shell commands you approve.

Doesn't
Prose or open-ended research.

🛡️

Warden

Reviews pull requests and changes: the whole change first, then the few things that would matter.

Doesn't
Nitpicks, fixes, or posting anything you haven't approved.

How an expedition runs

You approve the plan. The crew does the walking.

1

Ask

Type a request in mission control or the terminal camp. If it could mean two things, the Quartermaster asks you one short question first.

2

Approve the plan

The plan fills in step by step. Approve it, change it, or set a budget for the whole expedition.

3

Quests set out

Up to four run at once. Each adventurer starts clean from a written brief, so nobody drags the whole conversation along.

4

Reports come home

The Quartermaster reviews each report, sends a failed check back to be fixed, and hands you one next step.

Camp rules

Clear limits, kept by the camp's own code.

An agent can't talk its way past these. The camp's own source is read-only to the crew, so nothing it reads can loosen them.

Secrets stay put

File tools never read .env, private keys or credentials, at any depth, even in a linked folder.

Shell asks first

Commands need your OK, stop after two minutes, and stop when you press Stop. A macOS sandbox is there if you want it.

Read-only git

Everyone can run status, diff, log and blame. Nobody pushes on their own.

No trampling

Parallel quests can't overwrite each other. A file changed by another quest has to be read again first.

Pages are information

Web pages, files and connector results are never treated as instructions, and suspected prompt injection is flagged.

Budgets hold

Spending is tallied after every reply, across all quests, and the run stops when the budget is reached.
